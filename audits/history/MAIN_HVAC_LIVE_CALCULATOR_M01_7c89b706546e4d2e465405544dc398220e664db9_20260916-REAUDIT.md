## PRIOR B FINDINGS — RE-AUDIT

### P1-01 — unsafe hard-coded Catalog fallback

**RESOLVED.** `project-catalog-pricing-engine.js` no longer uses hard-coded BOM-key-to-Catalog-ID defaults as an authoritative resolver. Current order is:

1. exact saved row `catalog_id`;
2. explicit persisted binding;
3. unique Catalog candidate declaring the BOM key and passing attribute compatibility;
4. multiple candidates remain `multiple_matches`;
5. no candidate remains `unresolved`.

Executable tests now verify both attribute mismatch and multiple compatible candidates fail to a provisional/operator-resolution state rather than receiving an arbitrary price.

This restores the required no-invented-Catalog-price invariant.

### P1-02 — impossible opening geometry silently clamped

**RESOLVED.** `project-load-engine.js` now checks `window area + door area > exposed wall area` before the conduction calculation and returns a blocked load with `load.opening_area_exceeds_exposed_wall_area`. Cooling/heating outputs remain null in that state.

Executable regression covers the impossible geometry case. The prior `Math.max(0, ...)` silent normalization path is removed from authoritative calculation.

### P1-03 — shallow extended history validation

**RESOLVED.** `project-history-core.js` now validates nested shape/status requirements for building envelope, load, equipment, electrical, mechanical BOM, priced BOM/totals, and compliance gate. Malformed nested dependency objects fail validation before staged import can commit.

Executable regressions cover empty equipment/electrical structures, missing priced rows, malformed compliance state and atomic malformed extended import.

### P2-01 — mixed residential/commercial load provenance

**RESOLVED.** `project-load-engine.js` now emits project-class-aware load source references: residential results do not carry the commercial IECC load source and commercial results do not carry the residential Manual J reference. Regression tests verify both directions.
