## FINDINGS

### F01 — P1 — Full-history import is not fail-closed / atomic

Requirement: malformed payloads must be rejected before history write.

Observed production behavior in `project-history-core.js`:

- `importPayload()` iterates history items independently;
- valid items are immediately accumulated into the returned store;
- invalid items increment `rejected` and processing continues;
- if at least one item is valid, return value is `ok: true` even when `rejected > 0`.

Observed caller behavior in `project-estimator-wizard.js`:

- when `r.ok` is true, `saveHistory(r.store)` is executed;
- therefore a mixed valid/malformed `project-calculation-history` payload produces a partial persistent import.

This violates the explicit task contract that malformed import payloads be rejected before any history write. The current core test covers all-valid import only and does not exercise mixed valid/invalid history atomicity.

Required correction: validate the complete incoming snapshot set first, without mutating the candidate store; if any required snapshot is malformed, return `ok:false` with the original normalized store and perform no write. Add an executable regression test proving mixed-validity history does not persist any imported snapshot.

### F02 — P1 — Imported snapshot totals are not constrained to numeric/null only

Requirement: `customerMaterials`, `yourCost`, `marginDollar`, and `marginPct` must be numeric or null.

Observed validation:

```text
s.totals[k] !== null && s.totals[k] !== undefined && !Number.isFinite(Number(s.totals[k]))
```

Consequences:

- `undefined` / missing total fields are accepted;
- numeric strings such as `"200"` are accepted;
- empty string `""` is accepted because `Number("") === 0`;
- booleans are coercible to finite numbers and are accepted.

This is weaker than the required schema contract and permits malformed financial snapshot data to enter local history. Existing history tests do not cover strict type rejection.

Required correction: require each named total field to exist and satisfy `value === null || (typeof value === 'number' && Number.isFinite(value))`. Add tests for missing keys, numeric strings, empty strings, booleans, NaN and infinities.

### F03 — P2 — Generated import IDs are not explicitly collision-checked

`importPayload()` replaces source IDs with locally generated IDs and preserves `importedFromId`, which prevents ordinary source-ID overwrite. However, the generated ID is not checked against existing/import-batch IDs before insertion. Collision probability is low but the task explicitly requires imported identity not to permit collision/overwrite.

Recommended correction: generate-until-unique against a set containing all current store IDs and IDs generated in the same import batch; add deterministic tests with a stubbed ID generator or injectable generator.
