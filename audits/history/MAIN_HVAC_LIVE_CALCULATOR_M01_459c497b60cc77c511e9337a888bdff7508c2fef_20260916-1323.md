## P1 FINDINGS

### P1-01 — Catalog resolver silently applies hard-coded product IDs without attribute compatibility

File: `project-catalog-pricing-engine.js`

Evidence:

```text
SAFE_DEFAULTS = {
  'line-set-ft':'ac-ls-17',
  'indoor-support':'ac-pd-06',
  'filter-drier':'ac-ls-16',
  'supply-outlets':'ac-du-14',
  'return-grilles':'ac-du-16',
  'duct-route':'ac-du-13',
  'equipment-support':'ac-pd-05'
}
```

`resolveCatalogId()` accepts this mapping before attribute/tag matching and returns `source:'safe-default'` whenever that Catalog ID exists.

Why this blocks A:
- S09 requires exact saved Catalog ID -> compatible category/attributes -> unresolved/multiple -> operator resolution.
- A row such as `equipment-support` can represent roof support, wall support, or pad/support, but the resolver maps all variants to one product ID without checking row attributes.
- This can silently attach a price to the wrong physical item, contradicting the no-invented-Catalog-price invariant.

Required correction:
- remove unconditional SAFE_DEFAULTS resolution from authoritative matching;
- allow only exact row Catalog ID, persisted operator binding, or unique compatible candidate with validated attributes/tags;
- otherwise remain unresolved/multiple.

### P1-02 — Invalid envelope geometry is silently normalized into a calculable load

File: `project-load-engine.js`

Evidence:

```text
opaqueWall = Math.max(0, wallArea - winArea - doorArea)
```

No blocker or provisional state is added when `window area + door area > exposed wall area`.

Why this blocks A:
- the audit task explicitly requires malformed geometry edge cases to be fail-closed or at least visibly provisional;
- clamping impossible geometry to zero hides invalid input and can understate conduction load while returning a seemingly usable result.

Required correction:
- detect opening area greater than exposed wall area;
- return blocked (preferred) with explicit blocker/missing/error code;
- add executable regression coverage.

### P1-03 — Extended snapshot import validation is structurally shallow

File: `project-history-core.js`

Evidence:
`validExtended()` only checks that seven top-level members are non-array objects, that `sourceRefs` is an array, and optionally validates `pricedBOM.totals`. It does not validate the nested shape/status/rows of load, equipment, electrical, mechanical BOM, priced BOM, or compliance state.

Why this blocks A:
- S11 requires strict, atomic import and malformed extended calculation chains to fail validation;
- payloads with empty `{}` dependency objects can satisfy the current top-level check and enter history as if they were extended live-chain snapshots.

Required correction:
- validate required nested fields for every extended dependency object;
- validate priced-BOM rows/totals and compliance status/blockers shape;
- preserve atomic failure before any staged import is committed;
- add malformed-chain fixtures.
